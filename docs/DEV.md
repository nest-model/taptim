# TAPTIM

**Потерял? Найдём. Не нужно? Передай дальше.**
Городской сервис Шымкента: потерянные и найденные вещи, бесплатная передача, обмен и запросы «ищу вещь».

React 19 · TypeScript (strict) · Vite · Tailwind CSS 4 · React Router · TanStack Query · React Hook Form + Zod ·
Supabase (Auth, PostgreSQL + RLS, Storage, Realtime, Edge Functions) · Vitest · Playwright · ESLint · Prettier

> Это техническое описание для разработчика. Пошаговый запуск — в [README](../README.md).

---

## Что внутри

| Раздел | Что работает |
|---|---|
| Главная | Город, поиск, две плитки быстрых действий, свежие объявления, персональные рекомендации (только при наличии данных), категории, правила безопасности. Никакой выдуманной статистики. |
| Потеряно / Найдено | Сегменты, чипы категорий, список, фильтры по району и датам, «Это моя вещь» с приметами, особый режим ценных находок (контакт только после заявки). |
| Отдам / Обмен / Ищу | Очередь желающих, одобрение, «Передано», обмен с подтверждением обеих сторон, запросы со сроком актуальности. |
| Поиск | Серверный полнотекстовый поиск (русская морфология + триграммы), фильтры: тип, категория, район, даты, «только с фото», закрытые; сортировка; пагинация. |
| Объявление | Галерея, бейджи, автор, «Написать», избранное, жалоба, «Похожие», совпадения потерянное↔найденное для автора. |
| Мастер публикации | 4 экрана (тип и категория → фото и описание → район и подробности → предпросмотр), черновики на сервере, автосохранение, защита от двойной отправки. |
| Аккаунт | Регистрация с подтверждением почты (PKCE), вход, восстановление и смена пароля, выход со всех устройств, принятие соглашения (проверяется сервером). |
| Профиль | Аватар, имя, описание, статистика, мои объявления, избранное, запросы и обмены, жалобы, блокировки, приватность, уведомления, удаление аккаунта с объяснением. |
| Чат | Realtime, непрочитанные, история с пагинацией, статусы отправки, повтор без дублей, блокировка, жалоба на сообщение, лимиты. |
| Модерация | Обзор, очередь жалоб с приоритетами, контекст переписки (с логированием), скрытие/одобрение, ограничения, апелляции, роли, журнал действий (append-only). |
| Темы | Светлая, тёмная, системная; выбор сохраняется; плавное переключение. |

Дизайн повторяет визуальный концепт TAPTIM: приглушённый зелёный, кнопки-«таблетки», мягкий лайм только для главной кнопки экрана, нижняя навигация «Главная · Потеряшки · Создать · Обмен · Профиль». Контраст токенов проверен по WCAG AA (см. `src/index.css`).

## Быстрый старт (локально)

Требования: Node.js 22+, Docker (для `supabase start`), [Supabase CLI](https://supabase.com/docs/guides/local-development).

```bash
npm install
supabase start                      # поднимает Postgres, Auth, Storage, Realtime
supabase db reset                   # применяет supabase/migrations
supabase functions serve            # Edge Functions (в отдельном терминале)
cp .env.example .env                # впишите URL и publishable key из `supabase status`
npm run dev                         # http://localhost:5173
```

Письма подтверждения при локальной разработке смотрите в Mailpit/Inbucket (`supabase status` покажет адрес).

### Первый администратор

Роли нельзя выдать из клиента. Один раз выполните в SQL-редакторе (после регистрации своего аккаунта):

```sql
insert into public.user_roles (user_id, role)
select id, 'admin' from auth.users where email = 'you@example.kz';
```

Дальше модераторов назначает админ в панели «Модерация → Пользователи».

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` / `build` / `preview` | разработка / сборка / предпросмотр сборки |
| `npm run lint`, `npm run typecheck`, `npm run format` | качество кода |
| `npm test` | unit-тесты (DB-тесты пропускаются без `DATABASE_URL`) |
| `npm run test:db` | поднимает временный PostgreSQL, применяет все миграции и гоняет тесты RLS/IDOR (нужны `initdb`/`pg_ctl` 15+) |
| `npm run test:e2e` | Playwright с мок-бэкендом; `E2E_LIVE=1` — против реального Supabase (см. `e2e/live.spec.ts`) |
| `npm run check:secrets` | проверка, что в `dist/` нет секретов |
| `npm run db:types` | генерация типов из локальной БД (`supabase gen types`). Без Docker: `DATABASE_URL=… node scripts/gen-types.mjs` |

## Принятые решения

- **Безопасность в базе, а не в интерфейсе.** Все права — RLS + column grants; все изменения статусов — SECURITY DEFINER RPC с проверкой роли и блокировкой строки. Подробно — [`docs/SECURITY.md`](SECURITY.md).
- **Rate limiting в PostgreSQL**, а не в памяти процесса, — работает глобально.
- **Фото** грузятся в приватный staging, а в публичный бакет их кладёт только Edge Function после проверки формата по сигнатуре и удаления метаданных (GPS, модель телефона).
- **Удаление объявлений**: черновики удаляются, опубликованные — мягко (нужны для разбора жалоб).
- **Геолокация не запрашивается**: район + ориентир. Карта подключается через абстракцию `src/lib/map/provider.ts`, без ключа приложение работает без неё.
- **Города, районы, категории** — в БД; новый город = строки в `cities`/`districts`.
- **Казахский язык**: инфраструктура готова (`src/i18n/kk.ts`, `name_kk` в справочниках), включается в `ENABLED_LANGS` после вычитки переводов носителем.
- **Push** не отправляются без провайдера: есть центр уведомлений + Realtime. Следующий шаг — Web Push (VAPID) через Edge Function.

## Ограничения и что сделать до публичного запуска

См. раздел «Оставшиеся риски» в [`docs/SECURITY.md`](SECURITY.md): CAPTCHA на регистрацию, юридическая вычитка документов, требования РК к локализации персональных данных, очистка Storage по срокам хранения.

> Примечание: присланное ТЗ обрывается на пункте 13 «Админ-панель… фильтрацию;». Панель реализована по разумному объёму (обзор, жалобы, объявления, пользователи, апелляции, журнал); если в ТЗ дальше были пункты — пришлите продолжение.
